# 纯眼动打字系统设计规格

日期：2026-08-11  
状态：会话设计已确认，等待书面规格复核

## 1. 目标

在独立目录 `D:\CodeX\脑电软件设计\cap32_gaze_typing` 中开发一套仅依赖摄像头眼动的打字系统。系统参考现有眼动项目的校准、注视坐标估计、平滑和漂移修正思路，也参考脑电打字器的分组键盘、文本编辑、实验记录和双程序交付形式，但不修改、导入或覆盖任何参考项目文件。

最终交付两个 Windows 程序：

- `眼动采集校准.exe`：摄像头连接、快速校准、可选精度验证、注视与眨眼数据输出。
- `纯眼动打字器.exe`：启动设置、眼动连接状态、凝视选字、菜单导航、文本编辑、发送和实验记录。

系统不包含脑电采集、FBCCA、SSVEP 频率刺激或脑电与眼动融合逻辑，也不向网络发送用户文本或眼动数据。

## 2. 隔离原则

- 新版拥有独立的源码、测试、配置、日志、校准文件、构建脚本和 Git 历史。
- `D:\claude\新协议版` 仅作为眼动算法思路的只读参考。
- `D:\CodeX\脑电软件设计\cap32_brain_typing` 仅作为打字交互与打包方式的只读参考。
- 新程序运行时不依赖上述两个目录，删除或移动参考目录后仍应能够独立运行。
- 用户数据写入 `%APPDATA%\PureGazeTyping`，不写入参考项目目录。

## 3. 总体架构

### 3.1 眼动采集校准程序

职责：

- 枚举并打开摄像头，显示采集状态和简洁的人脸取景预览。
- 加载人脸关键点与眼动估计运行时。
- 执行快速校准、可选精度验证和校准重置。
- 生成平滑后的屏幕注视坐标与眨眼状态。
- 通过本机 UDP 向打字器发送眼动采样和在线状态。
- 保存与当前显示器、缩放比例和摄像头对应的校准模型。

### 3.2 纯眼动打字程序

职责：

- 在开始页显示眼动连接、摄像头和校准状态。
- 提供“显示眼动位置”和“凝视停留时间”设置。
- 显示静态高对比度分组键盘，不产生频率闪烁。
- 对有效注视数据进行目标命中、停留累积、防重复触发和菜单导航。
- 支持三次眨眼快捷返回。
- 管理当前文本、历史文本、删除、空格、清空、暂停和发送。
- 保存逐采样记录、交互事件和最终文本。

### 3.3 共享模块

两个程序使用同一份版本化布局定义和本机协议定义：

- `layout`：屏幕坐标、顶栏和六个目标区域的几何计算。
- `protocol`：眼动采样、在线状态和校准状态的数据结构。
- `settings`：配置校验、持久化和默认值。

共享布局是保证校准界面与实际打字界面吻合的唯一坐标来源，两个程序不得各自复制一套坐标常量。

## 4. 菜单与屏幕布局

纯眼动版统一使用两行三列的六个大目标，主菜单、字母子菜单和功能菜单的目标中心、尺寸与边距完全相同，页面切换只改变文字和命令。

### 4.1 主菜单

六个目标依次为：

1. `A-E`
2. `F-J`
3. `K-O`
4. `P-T`
5. `U-Z`
6. `功能`

### 4.2 字母子菜单

- `A-E` 至 `P-T` 页面显示五个字母和一个空格目标。
- `U-Z` 页面显示六个字母。
- 所有子菜单在顶栏固定显示大尺寸返回按钮，不占用六个字母目标。
- 返回按钮的位置与命中区域固定，并纳入校准布局。

### 4.3 功能菜单

六个目标为：删除、空格、发送、清空、暂停和返回。清空需要二次凝视确认，避免误操作；发送只在本地确认并保存当前内容，不调用网络接口。

### 4.4 视觉反馈

- 注视进入目标后，目标边框按停留进度逐步填充。
- 选中时显示短暂确认边框并执行命令。
- “显示眼动位置”关闭后，只隐藏实时注视点；目标进度和选中反馈仍然显示。
- 页面布局不因注视点、进度、提示文字或连接状态而移动。

## 5. 快速校准

### 5.1 校准界面一致性

校准程序使用与打字器相同的全屏窗口尺寸、系统缩放、顶栏、两行三列目标区域和返回按钮位置。校准时以高亮圆点替代按键文字，但圆点中心必须等于实际交互目标中心。

### 5.2 默认流程

1. 用户选择摄像头，并选择是否勾选“校准后进行精度验证”；该选项默认关闭。
2. 用户自然坐姿注视中心参考点约 `1.0 秒`。
3. 程序依次高亮固定返回区域和六个菜单目标，每个位置采集约 `0.8 秒`。
4. 每个位置至少取得 12 帧有效、非眨眼样本后立即进入下一位置。
5. 若样本不足，仅延长当前位置；单个位置达到 3 秒仍不足时暂停并提示调整坐姿或光线。
6. 正常情况下快速校准在 `8-10 秒`内完成，只采集一轮。

### 5.3 可选精度验证

- 未勾选时，满足最低有效样本数后直接保存校准。
- 勾选时，对六个核心菜单区域进行一次约 `5-7 秒`的快速命中检查。
- 命中不少于 `5/6` 时直接保存。
- 未达到 `5/6` 时提供“只重校异常区域”和“仍然保存”两个明确操作，不强制重做全部校准。

### 5.4 校准数据约束

校准记录包含校准版本、屏幕分辨率、系统缩放比例、摄像头编号、布局版本和时间。环境不匹配时，打字器显示不兼容状态并要求重新校准。

用户点击“开始实验”后，准备画面提供约 `1 秒`的中心注视，用于估计本次坐姿造成的小幅整体偏移。该步骤不重新训练模型，也不显著增加启动时间。

## 6. 开始设置

`纯眼动打字器.exe` 启动后先显示设置页，不直接进入全屏打字：

- 眼动连接状态：未连接、已连接、数据无效或校准不匹配。
- 显示眼动位置：首次运行默认开启，之后记住上一次选择；开始前可以修改。
- 凝视停留时间：默认 `1.0 秒`，范围 `0.5-3.0 秒`，步长 `0.1 秒`。
- 开始实验：只有在眼动数据在线且校准兼容时才可用。
- 结束或退出全屏后返回设置页，用户可以重新调整选项。

实验过程中设置锁定，避免参数在同一会话内意外变化。

## 7. 凝视停留判定

### 7.1 状态规则

- 只有有效、人脸存在、非眨眼且质量达到最低要求的注视采样参与停留累计。
- 注视进入某个目标后开始累计。
- 注视离开不超过 `0.2 秒`时暂停但保留进度，用于容忍短暂抖动。
- 离开超过 `0.2 秒`、切换到其他目标或连接失效时清空当前进度。
- 达到用户设置的停留时间后触发一次选择。
- 触发后必须离开该目标至少 `0.3 秒`才能重新武装，避免连续误选。
- 眨眼期间暂停停留，不把闭眼或睁眼过程当作目标移动。

### 7.2 返回主菜单

返回采用双保险：

- 主要方式：凝视子菜单顶栏的固定返回按钮。返回按钮至少使用用户停留时间，且不短于 `1.2 秒`。
- 快捷方式：约 `2.5 秒`内完成三次有效眨眼，立即取消当前停留并返回主菜单。

三次眨眼只统计“闭眼后重新睁开”的完整事件。单次闭眼持续时间必须处于合理范围，摄像头丢失、长时间闭眼和人脸遮挡不得计数。界面短暂显示 `眨眼 1/3` 和 `眨眼 2/3`；第三次成功后返回。已经处于主菜单时不执行返回动作。

## 8. 本机通信

两个程序通过回环地址上的 UDP 通信，默认端口为 `9101`。协议采用带版本号的 UTF-8 JSON 数据包。

眼动采样至少包含：

- 协议版本、消息类型和时间戳。
- `valid`、`face_detected`、`blink`、`quality` 和估计帧率。
- 有效时的平滑屏幕坐标和可选原始坐标。
- 校准标识和布局版本。

采集程序每秒发送在线状态消息，用于报告摄像头、校准和采样状态。这里的“在线状态”只表示本机进程仍在工作，不涉及互联网连接。

打字器连续约 `2 秒`未收到在线状态或眼动采样时：

- 清空当前停留和眨眼序列。
- 暂停所有凝视选择。
- 显示“眼动连接中断”。

恢复后需连续收到一小段有效数据才自动继续，防止单个偶发数据包解除暂停。

## 9. 数据与日志

运行数据写入 `%APPDATA%\PureGazeTyping`：

- `calibration/`：校准模型和兼容性元数据。
- `settings.json`：用户设置。
- `logs/`：UTF-8 运行日志。
- `sessions/<会话时间>/gaze_samples.csv`：时间戳、坐标、有效性、质量、眨眼、命中目标和停留进度。
- `sessions/<会话时间>/events.csv`：页面切换、选中、返回、暂停、断线和发送事件。
- `sessions/<会话时间>/result.txt`：最终确认文本。
- `sessions/<会话时间>/session.json`：设置快照、校准标识、屏幕环境和会话摘要。

写入失败时程序应继续运行并在界面中提示记录异常；不得因单次日志错误中断输入。发送操作始终先落盘，保存失败时不显示发送成功。

## 10. 异常处理

- 摄像头打不开：显示摄像头编号与可执行的重试/切换操作。
- 人脸持续丢失：暂停校准或打字，不用旧坐标继续选择。
- 校准不兼容：禁止开始实验，并显示需要重新校准的具体原因。
- UDP 端口占用：提示端口和占用错误，不静默切换到未知端口。
- 数据格式或版本错误：丢弃该数据包并记录限频警告。
- 打字器异常退出：已写入的逐行 CSV 和日志保持可读，下一次运行不覆盖旧会话。

## 11. 技术边界

- UI 使用 PySide6；静态键盘不依赖 PsychoPy 的闪烁时序。
- 摄像头读取使用 OpenCV，眼动估计采用新项目内部封装的 EyeTrax/人脸关键点运行时。
- 几何、停留判定、眨眼手势、打字状态机、协议和记录器保持为独立可测试模块。
- 两个可执行程序共享代码模块，但分别拥有清晰入口和进程生命周期。
- 发布包为 onedir 结构，运行时依赖随程序分发，不要求用户选择 Python、JSON 或桥接器路径。

## 12. 测试策略

### 12.1 自动测试

- 布局：不同分辨率和缩放比例下，校准目标与打字目标坐标一致且不重叠。
- 校准：有效帧门槛、单点延长、可选验证、`5/6` 判定和环境兼容性。
- 停留：默认时间、用户修改、短暂离开容错、超时清零和离开后重新武装。
- 注视点显示：关闭后不绘制注视点，但选择结果完全相同。
- 眨眼：单次、双次、三次、过慢、长闭眼、丢脸和冷却期。
- 菜单：五组字母、`U-Z`、功能菜单、固定返回按钮和三眨眼返回。
- 通信：乱序、坏包、超时、恢复和协议版本不匹配。
- 记录：成功写入、写入失败、会话隔离和最终文本一致性。
- 打包冒烟：两个入口均能启动，模块和模型资源完整。

### 12.2 硬件验收

- 使用目标摄像头完成一次不超过约 10 秒的快速校准。
- 分别以显示和隐藏注视点运行完整输入流程。
- 使用默认停留时间输入字母、空格和删除，并完成发送保存。
- 在字母子菜单中分别验证凝视返回和三次眨眼返回。
- 拔出或占用摄像头验证暂停，恢复摄像头后确认自动继续。
- 改变分辨率或缩放比例后确认校准不兼容提示。

## 13. 验收标准

- 新版全部文件位于独立项目或自身应用数据目录，两个参考项目无文件变化。
- 用户无需脑电设备即可完成校准、输入、编辑、返回、暂停和发送。
- 开始页可以选择是否显示实时眼动位置，并可以修改停留时间。
- 隐藏注视点不会改变凝视选择行为。
- 正常环境下快速校准约 `8-10 秒`，精度验证为默认关闭的可选项。
- 校准和打字使用同一布局定义，目标位置不存在双份硬编码。
- 连接中断或无效眼动不会触发按键。
- 每次实验产生独立、可读且足以复盘的本地记录。
- 发布目录包含可独立启动的 `眼动采集校准.exe` 和 `纯眼动打字器.exe`。

## 14. 非目标

- 不实现脑电输入或脑电眼动融合。
- 不实现联网账号、云同步、远程发送或多人协作。
- 不在首版加入屏幕键盘之外的鼠标控制功能。
- 不追求跨平台发布；首版目标为当前 Windows 环境。
