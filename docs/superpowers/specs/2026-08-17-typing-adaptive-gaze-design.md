# 纯眼动打字器会话级实时自适应设计

## 目标

把 `D:\claude\新协议2_实时自适应眼动融合版` 中经过门控的会话仿射与 Huber-RLS 更新思路迁移到纯眼动打字系统，在不覆盖基础校准模型、不修改参考工程的前提下，减小使用过程中的缓慢漂移和局部系统偏差。

## 已确认选择

- 采用方案 1：自适应算法运行在 `纯眼动打字器.exe` 内。
- 启动设置新增“实时自适应校正（推荐）”，默认开启并允许关闭。
- `眼动采集校准.exe` 继续只负责基础 EyeTrax 估计、固定屏幕仿射、质量判断与 UDP 输出。
- 在线修正只在当前打字会话内生效，不写回 Ridge 模型、基础校准元数据或校准目录。

## 不变量

- 母菜单、子菜单、按键位置、停留时间、三次眨眼返回和发送换行行为保持不变。
- 关闭自适应开关时，坐标路径与当前版本一致。
- 显示或隐藏注视点只影响绘制，不影响选择和自适应判断。
- 校准编号或布局版本变化时，不复用旧会话矩阵。
- 无效 gaze、眨眼、人脸丢失、准备阶段和未成功触发的停留不得产生训练锚点。
- 不修改 `D:\claude\新协议2_实时自适应眼动融合版`。

## 架构

```text
眼动采集校准.exe
  -> Ridge 基础预测
  -> 固定 screen_affine
  -> Kalman/EMA
  -> gaze UDP

纯眼动打字器.exe
  -> 启动中心点平移修正
  -> 会话级受约束 affine
  -> 母菜单/子菜单命中与停留判定
  -> 成功选择后的可信锚点门控
  -> Huber-RLS 小步更新或拒绝/回滚
```

新增独立模块 `adaptive_gaze.py`，只负责稳定窗口、矩阵检查、RLS 更新、回滚和状态快照。`TypingController` 负责提供时间序列、当前页面矩形和成功触发的目标，不在控制器中实现矩阵数学细节。

## 坐标与状态流

每个 gaze 消息都进入稳定窗口，以便计算无效比例；其中只有有效且非眨眼的坐标先经过现有 `CenterDriftCorrector`，再进入会话仿射矩阵。修正后的坐标同时用于注视点显示、命中测试和停留判定。

控制器保留最近约 `0.55` 秒的样本，样本记录包含时间、中心修正后的坐标、有效性、眨眼和质量。出现以下任一情况时清空窗口：

- 页面从母菜单切换到子菜单或返回母菜单；
- 校准编号变化；
- 新会话开始或会话结束；
- 连续无有效人脸达到现有断流门限；
- 发生发送、删除、空格等页面状态重置动作。

## 可信锚点门控

只有 `DwellSelector` 已成功触发一个目标时才评估在线更新。目标中心不是自动真值，必须同时满足以下条件：

- 最近 `0.55` 秒至少 8 个有效且非眨眼样本；
- 无效样本比例不高于 25%；
- 有效样本到中位点的距离 MAD 不高于 38 px；
- 最近样本的中位点仍命中刚刚触发的目标；
- 中位点位于目标矩形内部 65% 核心区；
- 当前点到目标中心的残差不超过屏幕对角线的 18%；
- 该目标不是通过三次眨眼产生的返回动作。

核心区门控确保算法只修正已经较可靠的样本，不会把整块按键区域中的任意点强行拉向中心，也不会在误入相邻区域时继续强化错误。

## Huber-RLS 更新

会话矩阵采用 `3 x 2` 二维仿射形式，并围绕屏幕中心进行归一化计算。初始矩阵为单位矩阵。

默认参数沿用参考版的保守值：

- 遗忘因子：`0.995`；
- Huber 阈值：`90 px`；
- 单次最大修正：`12 px`；
- 初始协方差：`60`；
- 历史可靠矩阵：最多 8 个。

候选矩阵必须满足：

- X/Y 缩放均位于 `0.80 .. 1.25`；
- 旋转绝对值不超过 `10` 度；
- 错切绝对值不超过 `0.12`；
- 平移绝对值不超过对应屏幕尺寸的 `18%`；
- 条件数有限且不超过安全上限；
- 更新后的锚点残差不能大于更新前。

合法候选才提交。连续 3 次危险拒绝时回滚到上一可靠矩阵，并把当前会话的在线学习状态设为暂停；坐标输出继续使用回滚矩阵，不伪造 gaze 有效性。新会话或新的校准编号会恢复单位会话矩阵并重新允许学习。

## 设置与界面

`TypingSettings` 新增布尔字段 `adaptive_correction_enabled=True`。启动设置页增加复选框“实时自适应校正（推荐）”。

设置加载兼容旧三字段 JSON：缺少新字段时补默认值 `True`；未知字段或类型错误仍按当前容错规则处理。保存后写出新四字段格式。

主打字界面不新增持续占位的说明文字。现有顶部状态只在发生回滚或暂停学习时显示短提示，不干扰凝视区域。

## 日志与可追溯性

会话记录增加以下事件：

- `adaptive_update_accepted`：矩阵版本、更新前后残差和 Huber 权重；
- `adaptive_update_rejected`：拒绝原因和残差；
- `adaptive_rollback`：回滚次数和矩阵版本；
- `adaptive_reset`：新会话、校准变化或布局变化；
- `adaptive_disabled`：用户关闭开关。

日志只保存数值和状态，不保存摄像头图像。基础校准模型与元数据保持不变。

## 错误处理

- 非有限坐标、矩阵奇异、样本不足和时间倒退均拒绝更新，不中断输入。
- 自适应模块内部异常由控制器记录并回退到最后可靠矩阵；不会导致界面退出。
- 关闭自适应后立即恢复“中心平移修正后的坐标”，并清空在线窗口。
- 校准标识不兼容时沿用现有禁止打字逻辑，不进行自适应。

## 测试与验收

单元测试覆盖：

- 旧设置文件向四字段格式兼容；
- 稳定窗口的样本数、无效比例、MAD 和核心区门控；
- Huber 权重、最大步长、仿射约束、残差改善、拒绝和回滚；
- 母菜单和子菜单使用各自真实目标矩形；
- 关闭开关时坐标与旧版本一致；
- 页面切换、校准变化和新会话重置状态；
- 显示/隐藏 gaze 不改变选择或更新结果；
- 自适应事件写入会话日志。

集成验收包括全量测试、PyInstaller 构建、两个打包程序自检，以及发布版真实启动、UDP 输入、停留选择、关闭窗口和进程退出检查。真实准确率仍需使用当前摄像头和实际坐姿分别对比“自适应开启/关闭”的命中表现。
